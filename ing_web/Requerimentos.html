1. Descripción general del proyecto

1.1 Problema o necesidad identificada

Actualmente, la empresa NetPlus utiliza el sistema Z-BioTime para el registro biométrico de su personal. El problema radica en que la plataforma solo exporta los datos crudos en formato Excel, obligando al Asistente de Recursos Humanos a realizar diariamente una revisión manual exhaustiva para cruzar marcaciones, calcular atrasos y registrar justificaciones. Esta carga operativa es ineficiente, propensa a errores humanos y retrasa la consolidación mensual necesaria para el pago de la nómina.

1.2 Objetivo de la aplicación web

Desarrollar un sistema web interactivo (Dashboard de Nómina) que automatice la importación, validación y procesamiento de los reportes Excel de Z-BioTime y los reportes de ausencias. El sistema proporcionará un control diario de la puntualidad y generará automáticamente el resumen mensual consolidado, liberando al área de RRHH de tareas repetitivas.

2. Identificación de usuarios

Los usuarios que interactuarán con la aplicación en su primera versión son:

  • Asistente de RRHH (Operativo): Responsable de cargar diariamente los reportes Excel de marcaciones y ausencias, revisar el dashboard de puntualidad del día, resolver registros incompletos y generar el resumen del corte mensual para Contabilidad.
  • Jefatura de RRHH / Administrador (Estratégico): Responsable de visualizar indicadores globales de ausentismo, configurar parámetros del sistema (horarios, tolerancias) y auditar el registro de modificaciones.

3. Requisitos funcionales

Código Nombre Descripción
RF01 Carga de marcaciones El sistema debe permitir al usuario subir el archivo Excel de registros diarios exportado desde Z-BioTime.
RF02 Carga de ausencias/permisos El sistema debe permitir la importación de un segundo reporte/Excel que contenga los colaboradores que se encuentran fuera de la oficina o con permiso aprobado.
RF03 Validación de archivos El sistema debe detectar automáticamente si el Excel subido tiene formatos inválidos, columnas faltantes o datos duplicados antes de procesarlo.
RF04 Cálculo de atrasos El sistema debe comparar la hora de entrada real del colaborador contra su horario asignado y calcular los minutos exactos de atraso.
RF05 Identificación de registros incompletos El sistema debe alertar al Asistente de RRHH sobre marcaciones "huérfanas" (ej. un colaborador que timbró su entrada pero no su salida).
RF06 Dashboard diario El sistema debe presentar de forma gráfica un resumen del día consultado: total de presentes, ausentes, atrasados y colaboradores con permisos.
RF07 Historial individual El sistema debe permitir buscar a un colaborador por su nombre o código y mostrar su registro histórico de puntualidad.
RF08 Generación de reporte de nómina El sistema debe consolidar mensualmente los días laborados, total de minutos de atraso y ausencias injustificadas por cada colaborador.
RF09 Exportación de datos El sistema debe permitir la descarga de los resúmenes diarios y el reporte mensual de nómina en formato PDF y Excel.
RF10 Control de acceso (Login) El sistema debe requerir la autenticación de los usuarios mediante credenciales válidas (correo y contraseña).
RF11 Bitácora de auditoría El sistema debe guardar un registro inmutable de qué usuario subió cada archivo, la fecha, la hora y el resultado de la importación.

4. Requisitos no funcionales

Código Categoría Descripción
RNF01 Seguridad Las contraseñas de los usuarios deben almacenarse mediante algoritmos de encriptación (hash) y nunca en texto plano.
RNF02 Usabilidad / Diseño La interfaz debe ser intuitiva y construida respetando la identidad visual corporativa de NetPlus, utilizando su paleta de colores: verde, blanco y azul.
RNF03 Usabilidad El flujo principal (cargar un archivo Excel y visualizar el dashboard diario) debe poder completarse en un máximo de 3 clics.
RNF04 Compatibilidad La aplicación web debe ejecutarse correctamente en las versiones más recientes de Chrome, Edge y Firefox sin pérdida de funcionalidades.
RNF05 Compatibilidad de archivos El procesador de datos debe ser capaz de interpretar nativamente los archivos .xlsx de Z-BioTime sin requerir conversiones previas a CSV.
RNF06 Rendimiento El dashboard de indicadores debe renderizar las gráficas y estadísticas en un tiempo menor a 3 segundos.
RNF07 Arquitectura El backend de la aplicación debe estructurarse mediante un servidor Apache, permitiendo la futura conexión estructurada a bases de datos relacionales.

5. Alcance inicial del proyecto

Funcionalidades incluidas en la primera versión:

  • Autenticación y roles de usuario.
  • Importación, lectura y limpieza automática de datos desde archivos Excel (.xlsx).
  • Dashboard visual para el seguimiento de la puntualidad y ausentismo.
  • Exportación de reportes consolidados mensuales en formatos estándar.

Fuera del alcance de esta versión:

  • Conexión directa a nivel de base de datos o API nativa con el hardware del reloj biométrico Z-BioTime.
  • Cálculos contables/financieros para el rol de pagos (deducciones de ley, impuestos).
  • Portal de autoservicio o aplicación móvil para que los colaboradores envíen sus justificativos médicos.
