Requisitos Funcionales (RF) Requisitos No Funcionales (RNF)

27 requisitos, 19 en el MVP

ID Nombre Declaración (EARS) Criterio de aceptación Prioridad
RF-001 Carga de archivos CUANDO RRHH cargue los Excel de marcaciones, permisos, horas extras, vacaciones y horarios, EL SISTEMA DEBE extraer y procesar la información. Archivos importados a la base sin pérdida de registros. Must
RF-002 Validación de estructura MIENTRAS se procesan archivos, CUANDO falten columnas obligatorias, EL SISTEMA DEBE detener la carga y alertar. La alerta indica el archivo, la hoja y la columna que falta. Must
RF-003 Dashboard diario CUANDO se consulte una fecha, EL SISTEMA DEBE mostrar los empleados ausentes y atrasados. Tabla con minutos de atraso calculados contra el turno asignado y su clasificación (leve, moderado, grave). Must
RF-004 Exportación mensual CUANDO Contabilidad finalice la revisión, EL SISTEMA DEBE exportar el consolidado en Excel y PDF. Descarga de ambos archivos con la estructura de nómina. Must
RF-005 Headcount y rotación DONDE existan datos históricos, EL SISTEMA DEBE calcular el headcount y la rotación general y por área. Gráficas visibles en el panel de DO. Should
RF-006 Control de roles CUANDO un usuario inicie sesión, EL SISTEMA DEBE restringir las vistas según su rol. Contabilidad no ve el dashboard diario; RRHH no ve indicadores de rotación. Must
RF-007 Recarga sin duplicados CUANDO RRHH cargue un reporte de fechas ya procesadas, EL SISTEMA DEBE reemplazar los datos previos de esas fechas. Cargar dos veces el mismo archivo no cambia el conteo; si trae cambios, se actualizan. Must
RF-008 Identificación de empleados EL SISTEMA DEBE identificar a cada empleado por su cédula y relacionarlo con su ID de Z-BioTime, nombre y área. Todo registro queda asociado a un empleado; los IDs desconocidos se listan en el reporte de la carga. Must
RF-009 Autenticación CUANDO el usuario ingrese credenciales válidas, EL SISTEMA DEBE dar acceso al panel de su rol. Las inválidas muestran error y tras 5 intentos fallidos la cuenta se bloquea 15 min. Must
RF-010 Horas extras del día CUANDO se consulte una fecha, EL SISTEMA DEBE mostrar quiénes hicieron horas extras, con horas, tipo y estado de la solicitud. La lista coincide con las solicitudes del reporte para esa fecha. Must
RF-011 Vacaciones y permisos CUANDO se consulte una fecha, EL SISTEMA DEBE mostrar quiénes están de vacaciones, con permiso o con cambio de turno. Se listan solo solicitudes aprobadas que cubren la fecha. Must
RF-012 Solicitudes pendientes EL SISTEMA DEBE mostrar las solicitudes pendientes en una lista aparte de las aprobadas. Las pendientes no suman a ningún total. Should
RF-013 Filtros CUANDO el usuario aplique un filtro, EL SISTEMA DEBE actualizar los resultados por fecha, área, colaborador, tipo de novedad y estado. Cada filtro reduce la lista al criterio elegido. Must
RF-014 Totales del día EL SISTEMA DEBE mostrar los totales del día: atrasos, ausencias, horas extras, vacaciones y permisos. Cada total coincide con la suma de las filas de su lista. Must
RF-015 Resumen por colaborador CUANDO Contabilidad seleccione un corte, EL SISTEMA DEBE generar por colaborador las horas trabajadas, horas extras aprobadas por tipo, atrasos, ausencias, vacaciones y permisos. Coincide con el cálculo manual de una muestra de colaboradores. Must
RF-016 Selección de corte CUANDO el usuario elija un mes, EL SISTEMA DEBE tomar del 21 del mes anterior al 20 del mes elegido y permitir cortes anteriores. Al elegir octubre se consulta del 21 de septiembre al 20 de octubre. Must
RF-017 Formato de exportación DONDE Contabilidad defina un formato de nómina, EL SISTEMA DEBE permitir ajustar el orden y los nombres de las columnas exportadas. La exportación respeta la configuración guardada. Should
RF-018 Indicadores de asistencia EL SISTEMA DEBE mostrar la tasa de atrasos, el ausentismo y las horas extras, totales y por área, con tendencia mensual. Se consultan por área y corte y coinciden con los datos cargados. Must
RF-019 Altas y bajas CUANDO DO registre o cargue una alta o baja, EL SISTEMA DEBE guardarla con fecha, área y motivo. Una baja modifica el headcount y la rotación del área. Should
RF-020 Permiso de carga CUANDO un usuario intente cargar archivos, EL SISTEMA DEBE permitirlo solo a RRHH. Contabilidad y DO no ven ni alcanzan el módulo de carga. Must
RF-021 Historial de cargas EL SISTEMA DEBE registrar cada carga con fecha, hora, usuario, archivos, registros procesados y errores. RRHH ve la última carga en la cabecera y el historial completo en su pantalla. Must
RF-022 Gestión de usuarios CUANDO DO cree, edite o desactive un usuario, EL SISTEMA DEBE aplicar el cambio de inmediato. Un usuario desactivado no puede iniciar sesión. Must
RF-023 Configuración EL SISTEMA DEBE permitir a DO editar el corte, la tolerancia de atraso, los rangos de atraso y los recargos de horas extras. Un cambio de parámetro se refleja en el siguiente cálculo sin tocar el código. Must
RF-024 Novedades por revisar CUANDO una marcación no tenga solicitud aprobada (salida posterior al horario, marcación sin par), EL SISTEMA DEBE listarla como novedad. Las novedades aparecen en una lista aparte y no suman a horas extras. Should
RF-025 Detalle por colaborador CUANDO el usuario seleccione un colaborador, EL SISTEMA DEBE mostrar sus marcaciones, turno y novedades del corte. El detalle coincide con el Excel de marcaciones de ese colaborador. Should
RF-026 Indicadores a PDF CUANDO DO lo solicite, EL SISTEMA DEBE exportar el panel de indicadores a PDF. El PDF replica los gráficos y filtros activos. Should
RF-027 Alertas por correo DONDE se active la opción, EL SISTEMA DEBE avisar por correo los atrasos y ausencias del día. Se envía un correo al cerrar la carga diaria. Could

14 requisitos de calidad

ID Categoría Declaración (EARS) Medida de aceptación Prioridad
RNF-001 Rendimiento EL SISTEMA DEBE procesar y consolidar la información de 100 colaboradores en menos de 1 minuto. Excel de 5 MB procesado en menos de 60 s sin timeouts. Must
RNF-002 Seguridad EL SISTEMA DEBE almacenar las contraseñas con hash Argon2. Ninguna credencial está en texto plano en la base. Must
RNF-003 Usabilidad EL SISTEMA DEBE aplicar la identidad visual de Nettplus mediante tokens de diseño. Cambiar la paleta o el logo se hace en un solo archivo de configuración. Must
RNF-004 Seguridad EL SISTEMA DEBE transmitir la información solo por HTTPS y mostrar a cada rol únicamente sus vistas. Ninguna página se sirve por HTTP; las rutas de otro rol devuelven acceso denegado. Must
RNF-005 Usabilidad EL SISTEMA DEBE permitir a un usuario sin formación técnica cargar un reporte y ver el resumen diario en 3 clics o menos desde el inicio. Prueba con un usuario de RRHH que cumple el recorrido. Should
RNF-006 Compatibilidad EL SISTEMA DEBE funcionar en las últimas versiones de Chrome, Edge y Firefox de escritorio. Pruebas automatizadas de las funciones principales en los tres. Must
RNF-007 Compatibilidad EL SISTEMA DEBE aceptar los .xlsx de Z-BioTime sin conversión manual. Los reportes de muestra se cargan sin modificarlos. Must
RNF-008 Confiabilidad EL SISTEMA DEBE conservar los datos de cortes anteriores y validar los archivos para evitar datos incompletos o duplicados. Una carga con error no altera los datos ya guardados (carga transaccional). Must
RNF-009 Mantenibilidad EL SISTEMA DEBE tener estructura modular y parámetros en configuración (corte, tolerancia, recargos, formato). Cambiar el corte 21-20 no requiere modificar el código de los reportes. Should
RNF-010 Rendimiento EL SISTEMA DEBE responder las consultas del dashboard en menos de 2 segundos. 95% de las consultas en menos de 2 s con un corte completo cargado. Should
RNF-011 Disponibilidad EL SISTEMA DEBE estar disponible en horario laboral. 99% de disponibilidad de lunes a viernes, de 07:00 a 19:00. Should
RNF-012 Respaldo EL SISTEMA DEBE generar un respaldo diario de la base de datos y conservar los últimos 30. Restauración de un respaldo probada al menos una vez. Should
RNF-013 Privacidad EL SISTEMA DEBE tratar los datos personales de los colaboradores conforme a la Ley Orgánica de Protección de Datos Personales de Ecuador y registrar los accesos a datos sensibles. Registro de auditoría de inicios de sesión, cargas y exportaciones. Must
RNF-014 Accesibilidad y diseño EL SISTEMA DEBE mantener contraste suficiente y verse bien en pantallas de escritorio desde 1366 px de ancho. Contraste mínimo AA (4.5:1) en textos y sin desplazamiento horizontal desde 1366 px. Should
